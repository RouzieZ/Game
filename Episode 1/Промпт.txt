Ты — опытный Godot-разработчик. Нужно разработать текстовую нелинейную игру-читалку в жанре зомби-апокалипсиса под Godot 4.x с дальнейшей возможностью публикации на Яндекс Играх.

# 1. Общая задача

Создай полноценный Godot-проект текстовой интерактивной игры по сценарию «После звонка».

Игра не 3D и не 2D-экшен. Это текстовая интерактивная история в формате “читалки”:

* игрок читает сцену;
* выбирает один из вариантов ответа/действия;
* выбор меняет параметры героя, инвентарь, отношения, флаги сюжета;
* игра переходит к следующей сцене;
* некоторые выборы доступны только при наличии предметов, флагов или нужных параметров;
* есть привалы, отдых, инвентарь, усталость, голод, здоровье, отношения со спутниками и несколько концовок.

Проект должен быть сделан так, чтобы сценарий легко расширялся через JSON-файлы без переписывания логики игры.

# 2. Технические требования

Используй:

* Godot 4.x;
* GDScript;
* Control/UI-based scenes;
* JSON для хранения сценария;
* локальные сохранения;
* подготовку к Web Export;
* подготовку к интеграции с Яндекс Игры SDK.

Не используй:

* C#;
* 3D-сцены;
* тяжёлые ассеты;
* внешние плагины, которые могут сломать Web Export;
* русские символы и пробелы в названиях файлов/папок;
* интерактивный ИИ внутри игры.

Проект должен быть лёгким, браузерным и подходящим для публикации в HTML5/Web.

# 3. Целевая платформа

Игра должна корректно работать:

* в браузере;
* на ПК;
* на мобильных устройствах;
* с мышью;
* с клавиатурой;
* с сенсорным управлением.

UI должен быть адаптивным:

* нормальное отображение на 16:9;
* нормальное отображение на мобильном экране;
* крупные кнопки выбора;
* читаемый текст;

* управление одной рукой на мобильном устройстве.

# 4. Название игры

Рабочее название:

«После звонка»

Жанр:

Текстовая нелинейная survival drama / интерактивная книга / зомби-апокалипсис.

# 5. Сюжетная основа

Главный герой — Артём Соколов, 17 лет.

Апокалипсис начинается во время обычного школьного дня. Сначала появляются тревожные новости, потом заражённый врывается в школу. Артёму нужно выбраться из школы, найти младшую сестру Милу, узнать судьбу матери и выбраться из города.

Главная тема игры:

Что важнее: выжить любой ценой или остаться человеком?

# 6. Основные персонажи

Врач. Знала о заражении больше, чем говорила. Оставляет подсказки сыну.

# 9. Усталость, здоровье и голод

Усталость:

* 0 — бодрый;
* 1 — уставший;
* 2 — измотан;
* 3 — на грани.

Голод:

* 0 — сыт;
* 1 — голоден;
* 2 — сильно голоден.

Здоровье:

* normal — норма;
* wounded — ранен;
* critical — тяжело ранен.

Если усталость достигает 3, некоторые опасные выборы должны становиться недоступными или получать ухудшенное последствие.

Если здоровье critical и игрок делает рискованный выбор, можно привести к плохой концовке.

```json
  "title": "Последний урок",

		{ "type": "flag", "target": "mother_clue", "value": true }

	  "next": "scene_1_2",

	}
  ]

```

Поддержи типы условий:


* flags;
* inventory;
* visited_scenes;
* текущие отношения;
* настройки.

Для локального сохранения используй Godot user://.

Нужны функции:

```gdscript

```

Дополнительно создай заготовку для облачных сохранений Яндекс Игр:

```gdscript

```

Пока можно сделать fallback: если SDK недоступен, использовать local save.

# 17. Подготовка к Яндекс Играм

Создай отдельный автолоад:

`res://scripts/YandexSDK.gd`

Он должен быть безопасной обёрткой. В редакторе Godot и локально игра должна работать без SDK.

Нужны методы:

```gdscript
init_sdk()
game_ready()
gameplay_start()
gameplay_stop()
show_fullscreen_ad()
show_rewarded_ad(callback)
save_data(data)
load_data()
is_available()
```

Если игра запущена не в Web или SDK недоступен, методы не должны ломать игру.

Для Web-сборки подготовь возможность вызова JavaScript через JavaScriptBridge.

Сделай комментарии в коде, где подключать Яндекс SDK в HTML-шаблоне.

Важно:

* Game Ready вызывать только тогда, когда главное меню уже доступно игроку;
* Gameplay Start вызывать при начале/продолжении игры;
* Gameplay Stop вызывать при открытии меню, паузе, рекламе, завершении сцены/концовки;
* реклама пока должна быть опциональной и не мешать прохождению;
* игра должна проходиться без покупок.

Крик оборвался резко, будто человеку закрыли рот ладонью.

# 24. Логика StoryManager

StoryManager должен:

* загружать story.json;
* находить текущую сцену по id;
* отдавать текст сцены;
* отдавать список выборов;
* проверять условия выбора;
* применять эффекты выбора;
* показывать result_text после выбора, если он есть;
* переходить к следующей сцене;
* запускать проверку концовок.

# 25. Логика ChoiceResolver

ChoiceResolver должен поддерживать:

* проверку условий;
* применение эффектов;
* изменение статов;
* добавление/удаление предметов;
* установку флагов;
* переход на сцену;
* переход на концовку;
* обработку недоступных вариантов.

# 26. Важные требования к качеству
